# Decisions

## Agreed with the user (2026-11-14)

- **Form**: a Chrome extension. A Tampermonkey userscript and a console snippet were the other options.
- **Behaviour**: badges on every search result card **plus** filters to hide titles. Badges alone was the other option.
- **Scope**: originally the search page only. Extended later the same day to every page with title cards, with badges and filters: home (`/storefront`), `/movie`, `/tv`, `/genre/...`, `/collection/...`, the watchlist and detail page carousels, including the super carousel posters and the top banner.
- **Location**: a separate project in its own directory.
- **Cache**: each title is requested at most once per 14 days. The cache lives in `chrome.storage.local`, which needs the `storage` permission. Plain `localStorage` without expiry was the other option. Refreshing on a 14-day TTL was the user's choice over a "clear cache" button or never refreshing.
- **Title page banner**: on `/detail/<id>` a large banner at the top shows the same three checks (subscription, audio, subtitles in the chosen language), read from the same cached detail data as the card badges.
- **Empty carousels**: when the filters hide every card of a carousel, the carousel (its title) stays on the page. Hiding the whole row was the other option.

## Implementation choices

- **Plain JavaScript, no build step.** The extension is one content script and one stylesheet, so it can be loaded unpacked straight from the directory. If the code grows, moving to TypeScript with a bundler is an option. That would be a user decision.
- **Only the `storage` permission.** The detail requests are same-origin from the content script, so no `host_permissions` or background worker are needed. `storage` does not show a warning when the extension is installed.
- **Subscription status from the DOM** (`data-card-entitlement`) rather than from the hydration JSON. It is simpler and also covers cards loaded later by scrolling. Cards without the attribute (super carousel posters, top banner, the odd regular card) take it from the detail JSON instead, so it is cached with the audio list and can be up to 14 days old.
- **Audio language from the lightweight detail JSON** (about 200 KB) instead of the HTML page (about 600 KB). See [ANALYSIS.md](ANALYSIS.md), steps 5 to 7.
- **Polish subtitles as a separate badge and filter** (agreed with the user), not merged with audio into one three-state badge. The data is the `subtitles` array in the same detail JSON, so it costs no extra request. Cache entries without `subtitles` count as expired.
- **Lazy checking** (agreed with the user, 2026-11-14). Only cards near the viewport are checked (`IntersectionObserver`, 200 px margin), with at most 3 requests at once. When a filter needs a card's data, cards within one screen height (a second observer, `rootMargin: '100% 0px'`) are checked too, but not the whole page: a page often has hundreds of titles, about 200 KB each. Filtering stays correct where the user looks, because hidden cards make the next ones move into the zone (in virtualized grids, which leave empty slots, the one-screen zone still checks ahead of scrolling). The queue is rebuilt on every update, in this order: the detail page's own title, the cards near the viewport, then the cards within one screen. So the cards on screen come first, and titles that scrolled away or left the page drop out before their request starts.
- **Cache** in `chrome.storage.local`: keys `audio:<detail id>` with `{tracks, subtitles, entitled, time}`, valid for 14 days. The whole cache is read into memory when a page loads, and expired entries are deleted then. A `chrome.storage.onChanged` listener shares results between open Prime Video tabs. Failed checks are not cached and show "<code> audio ?" and a "?" on the subtitles badge. They are not retried until the page is reloaded.
- **Filters** are stored in the page's `localStorage` under `apbs:filters` (an old `polish` key is read as `audio`).
- **Language choice** (agreed with the user): one language for both audio and subtitles, from a fixed list of seven (PL, EN, DE, ES, FR, IT, CS). It is not a free choice because each language needs a checked track-name pattern. The cache already holds every track name, so switching language costs no requests. Stored in `localStorage` under `apbs:settings`.
- **One language setting** (agreed with the user) for both the language to look for and the language of the panel and badges; a picker at the top of the panel. It defaults to the browser's language (`navigator.language`) when supported, otherwise English. A saved choice always wins.
- **Simplified view** (agreed with the user, 2026-11-14): a "show icons only" checkbox (agreed name) at the bottom of the panel, below the hidden count, a separator line and (since added) the grey out checkbox, as the least important setting; stored with the language in `apbs:settings` (`compact`). It applies everywhere, including the title page banner. Each badge becomes a coloured square (same green/red/grey as the text badges) with a white SVG icon: a padlock, open or closed (subscription), a speaker (audio), "CC" (subtitles), chosen by the user from a sheet of candidates after a ticket and a subtitles box proved unclear; the paths are Material Icons, used as CSS masks from data URIs in `content.css`. The icon and the separator line stay; on cards the logo shrinks and the icons sit in a row. A legend of the four icons (open and closed padlock, speaker, "CC", reusing the badge texts, without the colours) sits at the very bottom of the panel, shown only while the view is on (agreed with the user). Considered: emoji (look differs per system) and coloured icons without a background, crossed out for "no".
- **Grey out instead of hiding** (agreed with the user, 2026-11-14): a checkbox at the bottom of the panel, below the hidden count and the separator line, above "show icons only"; stored in `apbs:settings` (`dim`). With it on, a card that fails a filter gets `data-apbs-dimmed` (grayscale and opacity 0.3, full view on hover; an attribute, not a class, because Prime Video rewrites the card's `class` on hover and the card stayed coloured after the pointer left). The grey and fading go on every part of the card that does not hold the badges, not on the card itself, so the badges keep their colours (a filter on the card greyed them out too) instead of being hidden, so it differs from the coloured, dimmed unchecked cards. The panel count keeps the "hidden" text and includes these cards. Considered: the checkbox right under the filters, plain stronger fading, no hover effect, a separate "greyed out" count text.
- **Titles that are not checked yet are dimmed, not hidden,** when a filter is on (agreed with the user, 2026-11-14). They are hidden only once known to lack the chosen audio or subtitles language, or to be outside the subscription. A failed check ends the dimming, so the card is shown.
- **UI texts** are in a `TEXTS` dictionary in `content.js` (agreed with the user), not in `chrome.i18n`: the content script could then only follow the browser's language, not the panel's picker, and it would add `_locales` files and a manifest entry.
- **Re-rendering**: a `MutationObserver` on `document.body` re-applies badges and filter classes, batched with `requestAnimationFrame`. DOM writes happen only when something changed, so the observer settles.
- **Hiding in carousels**: a carousel card sits alone in an `<li>`, so the `<li>` is hidden instead of the card, otherwise an empty slot would remain. Grid cards are hidden directly.
- **Virtualized grids leave empty slots** (agreed with the user, 2026-11-14). Prime Video virtualizes long grids such as "Więcej do odkrycia" (see PRIME_VIDEO_DATA.md): removing cards from the layout there made the screen go empty while scrolling. So in those grids a hidden card gets `visibility: hidden` and keeps its slot. Other options considered: a heavily faded card instead of an empty slot, or the extension rendering its own list of matching titles (best result, but much more work and needs the pagination requests researched). A grid counts as virtualized once it has a `page-pagination-marker` or a spacer taller than 0, and is remembered as such, so its cards do not switch between collapsing and empty slots. Short grids such as "Najlepsze wyniki" still collapse.
- **The top banner is never hidden.** Its cards are stacked and faded in turn, and removing one would likely break the rotation. It only gets badges, placed below the title's text.
- **Branding** (agreed with the user): the extension's icon is shown in the panel header (with the name) and once per badge group: the badges sit in a dark frame with the icon on the left and a thin separator line between them (design from the user), so everything added to the page is clearly not Prime Video's own. The icon is a data URI in `content.css` (`--apbs-icon`), which avoids `web_accessible_resources`; if `icons/icon48.png` changes, regenerate the URI.
- **The panel** is shown on every page that has title cards, and hidden elsewhere. It is also hidden while the video player is open (agreed with the user, 2026-11-14), by a CSS rule on `body:has(#dv-web-player.dv-player-fullscreen)`, so it needs no code in `update()`.
- **Collapsing the panel** (agreed with the user, 2026-11-14), because it covered the video in the player: a minus button at the right end of the panel header collapses the panel to the extension's icon (a 32 px square with the blue border), which expands it on click. The state is stored in `apbs:settings` (`collapsed`). Texts `collapse`/`expand` in `TEXTS`, used as the buttons' tooltip and `aria-label`.
- **Warning about a changed Prime Video** (agreed with the user, 2026-11-14): a red block at the top of the panel when the detail requests mostly fail or when a JSON field is not found in any response (`audioTracks`, `entitlementType`, `subtitles`); thresholds in `findProblems` and in HOW_IT_WORKS.md. Texts are in `TEXTS` (`warnRequests`, `warnData`), with the JSON field names left as they are. While `subtitles` is flagged, subtitle badges show "?" and the filter does not hide, since "no subtitles" everywhere would be a wrong answer. Not done: detecting changed card markup (a page with links to `/detail/` but no matching card), which needs the panel to stay visible on such pages; and a `try/catch` around each card in `update()`.
